# ContentZavod — план построения

Ветка `ContentZavod` в репозитории `gavrik` — изолированно от продакшн-бота
(`master`), чтобы не сломать уже работающий пайплайн для Светланы
(`VK_POSTS`, `svet_bot`) во время разработки.

## Решение от 2026-07-16 — сузили фокус
Светлана отложена (у неё уже есть рабочий ручной пайплайн в master,
не трогаем — см. `clients/svetlana/NOTE.md`). Единственный клиент MVP —
**Олег**: личная страница ВКонтакте + Telegram-канал.

- Реализовано как три отдельных CLI-скрипта (не через `_ask_ai` из
  handlers.py — тот async и завязан на aiogram/Telegram; для CLI своя
  синхронная обёртка в `content_zavod/common.py`, тот же паттерн вызова

- **Решение от 2026-07-17:** роли НЕ схлопываем в "Копирайтер+" (см. CRITIQUE.md
  п.1) — оставлены три отдельные роли как в исходном ROLES.md.
- [x] `content_zavod/idea_generator.py` — читает `strategy.md`, выдаёт
      5-7 тем/неделю с рубрикой и рекомендуемым форматом (клип/карусель/
      текст) с учётом требований ВК; ведёт `topics_history.json`, чтобы не
      повторяться неделя к неделе
- [x] `content_zavod/scenarist.py` — на каждую тему: структура сценария
      (проблема → инсайт → вывод/призыв), с явным учётом формата (клип/
      карусель/текст) в структуре
- [x] `content_zavod/hook_master.py` — на каждый сценарий 3-5 хуков
      разных подходов (вопрос-провокация/цифра-факт/личное-признание/
      контраст/другое), с явным запретом на пустой кликбейт
- [x] Прогнано для Олега целиком: 7 тем → 7 сценариев → 7×5 хуков, все
      успешно. Требования ВК по продвижению (клипы/видео в приоритете,
      минус 50% охвата за внешние ссылки в посте, вовлечение важнее
      охвата, крючок в первых секундах/строках) встроены в промпты всех
      трёх шагов через общий блок `VK_PROMOTION_REQUIREMENTS`.
- **Найденный и исправленный баг конвейера:** `claude --print` — это
  полноценный агент, а не голая text-completion API; иногда путает
  промпт с системным напоминанием/шаблоном или спотыкается о свой
  permission-классификатор и возвращает непустой, но не-JSON текст.
  Обычный retry (на исключения/пустой ответ) это не ловил — добавлена
  `ask_for_json_with_retry` в `common.py`, которая дополнительно
  перезапрашивает вызов целиком, если ответ не парсится как JSON.

## Фаза 2-4 — надёжность конвейера (добавлено 2026-07-17, см. CRITIQUE.md п.4)
Каждый шаг конвейера (Идея → Сценарий → Хуки → Форматы) обязан:
1. Вызывать `_ask_ai` через обёртку с retry+backoff (например 3 попытки,
   backoff 5с/15с/45с) — не полагаться, что один вызов = один успех.
2. Сразу после успешного шага сохранять промежуточный результат на диск
   (`content_zavod/clients/oleg/drafts/<week>/<step>.json` или аналогично),
   чтобы обрыв сети на «Конвейере форматов» не терял уже готовые
   Сценарий+Хуки — оркестратор при перезапуске должен уметь продолжить
   с последнего сохранённого шага, а не с нуля.

## Фаза 3 — Конвейер форматов — ЗАВЕРШЕНО 2026-07-17
- [x] `content_zavod/format_pipeline.py` — читает `hooks_final_*.json`,
      на каждый сценарий модель сама выбирает наиболее подходящий хук из
      3-5 вариантов Мастера хуков (с обоснованием — финальное слово всё
      равно за человеком на Фазе 4) и генерирует все 4 формата разом
- [x] Прогнано для Олега: 7/7 сценариев, все форматы в пределах лимитов
      (пример: пост ВК 1248 симв., видео-сценарий 80с) — каждый пост
      заканчивается открытым вопросом для комментариев (сигнал ВК:
      вовлечение важнее охвата), внешних ссылок в теле постов нет
- [ ] Показ в Telegram пачкой, как `/newpost`, но на всю неделю разом —
      **отложено до Фазы 4** (это уже интерфейс Редактора, не генерация)
- **Спецификация лимитов по формату (добавлено 2026-07-17, см. CRITIQUE.md
  п.5)** — промпт конвейера должен явно передавать эти ограничения, а не
  полагаться, что модель "сама знает формат":
  - **Пост ВК:** до ~15000 символов технически, но для органического поста
    целимся в 800-1500 символов; первые ~150 символов — до обрыва "Показать
    полностью", там должен быть хук.
  - **Пост ТГ:** до 4096 символов на сообщение (лимит Bot API); для канала
    целимся в 400-900 символов, поддерживается Markdown/HTML-разметка.
  - **Карусель:** 6-10 слайдов, на слайд — заголовок (до ~60 символов) +
    короткий тезис (до ~120 символов), связный нарратив слайд-к-слайду.
  - **Видео-сценарий:** хронометраж 30-90 сек, структура хук(0-3с)/
    развитие/призыв к действию, покадровый текст с таймкодами.

- **Решение от 2026-07-17:** ветка `ContentZavod` смёржена в `master`
  раньше изначально запланированного порога "2-3 недели ручной проверки"
  (см. CRITIQUE.md п.2) — осознанное исключение пользователя именно для
  подключения Telegram-публикации, не отмена принципа в целом.
- [x] `/cz_publish` в `handlers.py` — по одному черновику за раз, кнопки
  "✅ Одобрить (в очередь)" / "⏭ Пропустить", решения сохраняются в
  `drafts/publish_state.json` (не переспрашивает уже обработанные темы)
- [x] **Публикация по расписанию (обновлено 2026-07-17):** одобрение
  ставит пост в очередь на ближайший свободный будний день в 10:00
  (`CZ_DAILY_HOUR` в handlers.py), а не публикует мгновенно — решение
  пользователя. Фоновый шедулер `_cz_scheduler_loop` в `bot.py` (тик
  раз в 5 минут) разбирает очередь и публикует, что подошло по времени;
  человеческое одобрение (нажатие кнопки) остаётся обязательным шагом
  из ROLES.md — меняется только момент публикации, не факт одобрения.
- [x] Публикация в `@textprodv` через существующего `@mayroden_bot`
- [x] **Обложки к постам (добавлено 2026-07-17):** генерируются в момент
  одобрения через **YandexART** (Yandex Cloud AI Studio). Перебор
  провайдеров: Nano Banana (Gemini) — ключ рабочий, но лимит на картинки
  = 0 без биллинга; Kandinsky/FusionBrain — сайт был недоступен со всех
  проверенных сетевых путей; YandexART — сработал после привязки
  платёжного аккаунта (~2₽/картинка). Фолбэк на текст без обложки, если
  генерация не удалась или ключей нет.
- [ ] ВК — остаётся **ручной** (карточка показывает текст поста для
  копирования): VK-токен заблокирован модерацией VK, не код-задача
- [ ] Одобрение с правкой текста прямо в Telegram — не реализовано,
  MVP только "одобрить как есть / пропустить"; правка — вне артефакта
  или через прямое редактирование JSON перед `/cz_publish`

## Критерий успеха MVP (добавлено 2026-07-17, см. CRITIQUE.md п.6)
Фаза 2 не начинается, пока этот критерий не зафиксирован и не согласован
с Олегом. Порог: за первые 2 недели регулярной публикации (минимум
3 поста/неделю на ВК и ТГ) — рост охвата/подписчиков относительно
предыдущих 2 недель на тех же каналах. Если роста нет — не продолжать
"на веру" ещё месяцы (это и была ошибка автора исходной методики),
а разбирать причину явно: тема, формат, частота или сам канал.

## Явно вне рамок (пока)
- Лид-магнит и автоворонка продаж (модули 4-6 методики) — это уже про
  монетизацию трафика, а не про производство контента; отдельная задача
  после того, как сам конвейер докажет себя на 2-3 неделях реальной публикации
- Нейро-аватары/видео-генерация — упомянуты в источнике как опция, не нужны
  для MVP (текст+карусели уже дают формат без камеры)
