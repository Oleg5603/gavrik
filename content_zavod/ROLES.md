# ContentZavod — роли и протокол

Мультиагентный конвейер контента для нескольких клиентов (Олег, Светлана,
далее могут добавиться другие) поверх существующей инфраструктуры Гаврика.
Формат описания — по той же методике, что и `CLAUDE.md` в master (роли +
порядок + передача данных), чтобы новый модуль не расходился по стилю с
уже принятым в проекте протоколом.

## Ключевой принцип (не нарушать)

**Ни один агент не публикует без подтверждения человека.** Это уже принятое
правило Гаврика (см. `CLAUDE.md`, роль "Редактор") и одновременно —
единственное, что в записи-источнике (`SOURCE.md`) отделяет рабочую систему
от провалившегося "контент-завода в лоб".

## Роли

| Роль | Что делает | Вход | Выход |
|------|-----------|------|-------|
| **Оркестратор (Продюсер)** | Определяет, для какого клиента запрос (Олег/Светлана/другой), какая платформа (ВК/ТГ), какой агент нужен дальше; ведёт очередь партий контента | Команда в Telegram / расписание | Вызов нужного агента с client-конфигом |
| **Стратег (Распаковщик)** | Разово (и раз в 2-4 недели на обновление) превращает бренд/продукт/боли ЦА клиента в контент-стратегию: рубрики, тон, запрещённые темы | `clients/<имя>/brand.md` | `clients/<имя>/strategy.md` (рубрики + тон) |
| **Генератор идей** | По стратегии выдаёт пачку тем на неделю (5-7 идей), избегая повторов с уже опубликованным | `strategy.md` + история публикаций | список тем недели |
| **Сценарист** | Одна тема → одна структура сценария (проблема → инсайт → вывод/призыв) | тема | сценарий (структура, не финальный текст) |
| **Мастер хуков** | 3-5 вариантов первой фразы/хука под сценарий | сценарий | варианты хуков |
| **Конвейер форматов** | Сценарий + выбранный хук → готовые тексты под каждый формат (пост ВК, пост ТГ, карусель-слайды, сценарий короткого видео) | сценарий + хук | 3-4 готовых черновика |
| **Редактор** (человек: Олег/Светлана) | Правит и одобряет черновики перед публикацией — обязательный шаг, не автоматизируется | черновики в Telegram | одобренный текст |
| **Публикатор** | Выкладывает одобренный текст в нужную соцсеть в заданное время (по аналогии с существующим `svet_bot`/VK API) | одобренный текст + время | опубликованный пост |
| **Аналитик** | Раз в 1-2 недели собирает охваты/реакции по опубликованному, передаёт выводы Стратегу | метрики платформы | заметки для `strategy.md` |

## Порядок выполнения (Workflow)

```
Стратег (разово + обновление раз в 2-4 недели)
   ↓
Генератор идей (раз в неделю, пачка 5-7 тем)
   ↓
Сценарист (на каждую тему)
   ↓
Мастер хуков (варианты хука)
   ↓
Конвейер форматов (сценарий+хук → черновики под все форматы)
   ↓
Редактор (человек) — правит/одобряет пачкой
   ↓
Публикатор — выкладывает по расписанию недели
   ↓
Аналитик (раз в 1-2 недели) → выводы обратно в Стратега
```

## Мультиклиентность

Каждый клиент — отдельная папка `content_zavod/clients/<имя>/`:
```
clients/
  oleg/
    brand.md       — кто, продукт, аудитория, боли (вход для Стратега)
    strategy.md     — рубрики и тон (выход Стратега)
    platforms.md    — какие соцсети, ссылки на токены в .env (без самих токенов)
  svetlana/
    ...
```
Токены и ключи — только в `.env`, по образцу существующего `BOT_TOKEN`/
`VK_TOKEN` в Гаврике; в `platforms.md` — только имена переменных.

## Передача данных между агентами

- Стратег → Генератор идей: `strategy.md` (рубрики, тон, запрещённые темы)
- Генератор идей → Сценарист: список тем (без сценариев)
- Сценарист → Мастер хуков: структура сценария (без хука)
- Мастер хуков + Сценарист → Конвейер форматов: сценарий + выбранный хук
- Конвейер форматов → Редактор: черновики всех форматов сразу, показываются
  в Telegram (аналогично существующему `/newpost`)
- Редактор → Публикатор: одобренный текст + выбранное время публикации
- Публикатор → Аналитик: факт публикации (что и когда вышло)
- Аналитик → Стратег: агрегированные выводы (не сырые цифры)

## Что переиспользуется из Гаврика (не писать заново)

- `_ask_ai` / `_run_anthropic_sdk` / `_run_claude_subprocess` — единая точка
  вызова модели, уже с ретраями и лимитами.
- Паттерн тикающего таймера ожидания (см. `cb_coach_preset`,
  `_dispatch_coach`) — использовать для любого шага дольше 5-10 секунд.
- Паттерн ручного одобрения из `/newpost` — Редактор работает так же.
