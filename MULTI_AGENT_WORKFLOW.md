# Оркестратор ПРОЕКТИРОВАНИЯ

Единая система управления проектами Gavryk. Реестр ролей, маршрутизация и проверки гейтов находятся в `multi_agent.py`; вызовы ролей выполняются обработчиком в `handlers.py`.

В реестре 12 ролей. Проектные задачи проходят отдельными последовательными модельными вызовами:
`Planner → Architect → Challenger → Developer → Reviewer → QA → Security → UX Tester → Protector → Controller`.
Designer и Copywriter включаются для задач с интерфейсом или текстами. Controller вызывается отдельно и только для чтения.

## Гейты

- Реализация: Reviewer обязан вернуть структурированный вердикт Approved с проверяемыми фактами; QA должен вернуть Passed и реальные результаты. Невалидный формат, отсутствие доказательств или критическое/высокое замечание блокирует переход к Security и дальнейшим ролям.
- Архитектура и релиз требуют подтверждения человека; этот маршрут запрещает слияние, публикацию и запуск production.
- Любое открытое замечание critical/high блокирует gate.

## Аудит

`workflow_state.json` содержит время запуска, роли, статусы вызовов и результат gate. Тексты запросов и ответов туда не записываются. Запись о завершении вызова подтверждает только то, что вызов вернул ответ; она сама по себе не означает одобрение роли. Gate Reviewer/QA открывается только при валидном JSON с фактическими основаниями.

## Ограничения эксплуатации

Это последовательные вызовы одного настроенного провайдера, не отдельные постоянные worker-процессы. Непрерывный мониторинг здоровья сервиса и автоматический production deploy не настроены. После обязательного review/слияния обновление работающего бота потребует перезапуска сервиса.
