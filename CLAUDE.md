# Гаврик — роли и протокол мультиагентной системы

Формализация по методике "Завод нейроагентов, урок 2": роли + порядок выполнения +
передача данных + точки интеграции = мультиагент. Здесь описан реальный протокол
Гаврика, не гипотетический пример.

## Роли (субагенты)

| Роль | Что делает | Где в коде |
|------|-----------|------------|
| **Оркестратор** | Claude, читает этот файл, определяет каких агентов запускать, управляет `/status`, `/pull`, `/manage` по всем проектам Олега | `handlers.py`, `projects_registry.py` |
| **Планировщик контента** | Хранит план постов (тема, план) для проекта Палкиной | `VK_POSTS` в `handlers.py` |
| **Копирайтер** | Готовит текст поста по выбранной теме из плана | `/newpost` → `_send_newpost_menu` |
| **Редактор** | Человек (Олег/Светлана) — правит текст перед публикацией. Мультиагент НЕ публикует без подтверждения | ручной шаг, обязателен |
| **Публикатор** | Выкладывает готовый пост через `svet_bot` или вручную на vk.com/misemia | внешний Telegram-бот, вне кода Гаврика |
| **Коуч** | Отдельная персона — коуч по финансовой эффективности, не даёт готовых решений, задаёт вопросы | `COACH_SYSTEM` в `handlers.py`, `/coach` |
| **Субагент-мастерская (Jarvis Architect)** | Разворачивает новых агентов на VPS, настраивает напоминания, разработку с нуля — вызывается, не выполняется самим Гавриком | см. `projects_registry.py` запись `jarvis-architect` |

## Порядок выполнения (Workflow)

```
План постов (VK_POSTS)
   ↓
Копирайтер готовит текст (/newpost)
   ↓
Редактор (человек) правит и одобряет
   ↓
Публикатор → svet_bot / вручную vk.com/misemia
```

Для управления проектами (не контентом):
```
Запрос "статус/разверни/обнови проект X"
   ↓
Оркестратор → projects_registry.get_status() / pull() / deploy()
   ↓
Если задача — "разверни агента с нуля" → делегировать Jarvis Architect
```

## Передача данных между субагентами

- Планировщик → Копирайтер: тема и план поста (`VK_POSTS[idx]`)
- Копирайтер → Редактор: готовый текст, показывается прямо в Telegram
- Редактор → Публикатор: одобренный текст, публикуется вручную через другой бот
  (сознательно НЕ автоматизировано — контроль человека обязателен на этом шаге)

## Инструменты и доступы (.env)

Ключи и токены — **только** в `.env`, никогда в коде или чате:
- `BOT_TOKEN` — токен Telegram-бота Гаврика
- `SITE_URL` — URL клиентского сайта (по умолчанию palkina-therapy.ru)
- см. `.env.example` за полным списком переменных

## Частые ошибки (из урока — проверено на практике)

- **Не открывать отдельный файл вместо папки** при работе с Claude Code — иначе
  не виден весь проект целиком
- **Ключи только в `.env`** — в этом репозитории уже была утечка токена в
  `jarvis-architect/knowledge/gavrik-recovery.md` (исправлено 2026-07-14,
  ротация токена ещё не выполнена — см. память проекта)
- Не усложнять систему сверх необходимого — 3-5 ролей достаточно для старта
- Каждая роль — одна конкретная задача, не смешивать ответственность
